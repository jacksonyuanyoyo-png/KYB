# 一键启动

给不熟悉这个仓库的人。一条命令把数据库、接口和网页在你自己的电脑上跑起来，然后用浏览器打开工作台。

这是本机演示，不是上线到服务器。真正的生产部署见 `docs/backend/12-production-launch.md`。

## 你要打开的东西

| 地址 | 是什么 |
| --- | --- |
| http://localhost:3000 | 员工用的网页工作台 |
| http://localhost:8000/api/docs | 接口说明，给排查问题的人看 |
| http://localhost:8000/health | 接口是否正常。正常时里面有 `"status":"ok"` |

## 先装这四样

装好之后不用再管前端目录、后端目录、数据库命令。

1. **Docker Desktop**，并且要打开，等到它显示正在运行。  
   https://www.docker.com/products/docker-desktop/
2. **Node.js 22**（安装包里带 npm）。  
   https://nodejs.org/
3. **uv**（用来安装 Python 接口的依赖）。在终端执行：

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

装完后关掉终端再开一个，让 `uv` 进入命令路径。脚本发现电脑上没有 Python 3.12 时，会自己用 uv 装一个。

Windows 请用 **Git Bash** 或 **WSL** 运行下面的脚本，不要用普通的 cmd。

## 启动

在仓库根目录（能看到 `scripts` 文件夹的那一层）执行：

```bash
./scripts/up.sh
```

第一次会比较久：拉取数据库镜像、安装依赖、建表、写入 5 个用户和 7 笔演示案件。结束时终端会打印上面的网址。

然后再执行一次 `./scripts/up.sh` 是安全的：依赖会核对一遍，已有的案件不会被清掉。

## 停止

```bash
./scripts/down.sh
```

这只停网页和接口。数据库继续开着，案件还在。

连数据库容器一起停（数据仍保留，下次启动会再用）：

```bash
./scripts/down.sh --with-db
```

## 演示数据弄乱了，想恢复

这会删掉你在网页里改过的案件，恢复成最初的 7 笔演示案件：

```bash
./scripts/up.sh --reset
```

## 脚本实际做了什么

不需要记这些，出问题时可以对照。

1. 检查 Docker、Node.js 22、uv 是否可用。
2. 如果还没有配置文件，就生成 `services/api/.env.local` 和 `apps/web/.env.local`。已有文件不会覆盖。
3. 只用 Docker 启动 PostgreSQL（用户 `fcc`，库 `complex_accounts`，端口 5432）。不启动 Azurite。
4. 在 `services/api` 安装 Python 依赖，执行数据库迁移。库是空的才写入演示数据。
5. 在仓库根安装网页依赖，并编译共享规则包 `packages/domain`。
6. 启动 Python 接口（8000）和网页（3000）。

仓库里还有一个旧的 Nest 接口（`apps/api`，端口 4000）。一键脚本不会启动它。请不要用根目录的 `npm run dev` 代替本脚本，那条命令会把旧接口也拉起来。

日志在：

- `.run/api.log` 接口
- `.run/web.log` 网页

## 遇到问题

| 现象 | 怎么处理 |
| --- | --- |
| 提示 Docker 没在运行 | 打开 Docker Desktop，等它就绪后再执行 |
| 提示找不到 uv | 按上面的命令安装，然后新开一个终端 |
| 提示 Node 版本不够 | 安装 Node.js 22，终端里 `node -v` 应显示 v22 |
| 提示端口 3000 或 8000 被占用 | 先 `./scripts/down.sh`。若仍占用，是别的程序在用这个端口，停掉那个程序 |
| 网页能开，但是空的或和接口对不上 | 看 `apps/web/.env.local` 里是否有 `NEXT_PUBLIC_DATA_SOURCE=api` 和 `NEXT_PUBLIC_API_BASE_URL=http://localhost:8000`。改完后执行 `./scripts/down.sh` 再 `./scripts/up.sh` |
| 接口文档打不开 | 看 `.run/api.log`。数据库没起来时，先看 `docker compose ps` 里 postgres 是否 healthy |
| 想确认接口是好的 | 浏览器打开 http://localhost:8000/health ，应看到 `"database":"ok"` |

改过 `services/api/.env.local` 或 `apps/web/.env.local` 之后，需要停一次再启动，配置才会生效。
